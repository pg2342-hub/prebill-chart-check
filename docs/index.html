Pre-bill chart check

Pulls a day's urgent care visits over FHIR R4, reads each progress note, and checks the draft claim against it before the claim goes out. Each visit is released, auto-fixed, sent to the clinician, or held.

Why it matters

Most of what decides whether a claim is right lives in the note, not the claim. Checking only the claim's format sent every overbilled and unsigned visit out the door (14 of 30 matched). Rules that guess the visit level from orders and prescriptions avoided those critical misses but raised false alarms (22 of 30). With Claude reading the note and the same fixed rules deciding, 29 of 30 visits matched the answer key on all 3 runs.

What the first run caught

The first prompt passed 26/25/25 of 30 on its three runs, with 0 critical errors, so it did not clear the gate. Every miss was the same call: on 5 strep throat visits with a fever, Claude graded the problem as an acute illness with systemic symptoms, which would have sent a correctly billed 99213 to the clinician as under-coded. The AMA guidelines say fever or body aches in a minor illness treated for symptoms do not count as systemic. That rule went into the prompt, nothing else changed, and the second prompt passed 30/29/29 with 0 critical errors. The remaining miss is a close call: on a right lower belly pain sent for a CT, Claude twice read possible appendicitis as a threat to bodily function, where the answer key says an undiagnosed problem with uncertain prognosis. Because the fix was found on these same 30 visits, the next step would be fresh visits it has not seen. In a live pilot this is what shadow mode is for: the coders' rejections show which call is off before anything auto-fixes.

In this build, auto-fixes add modifier QW or 25 or swap an unspecified diagnosis for the one a positive test supports, and a visit level is never changed without the clinician. In the pilot plan, adding modifier 25 stays with the clinician until it clears the shadow bar.

The pull

The visits arrive the way they would from the EHR: a FHIR R4 search per encounter, with OAuth client credentials and the ah-practice parameter athenahealth documents for its FHIR API, against a local stand-in that throttles and expires tokens.

The same client also ran against the public HAPI FHIR R4 test server on 2026-11-25: it loaded the 188 synthetic resources, pulled 30 visits back over 183 search pages and 213 requests, and every field matched the source (CI run).

Data

All 30 visits, notes, patients, clinics and claims are synthetic and hand-labeled. The coding rules are a small subset of public ones: AMA 2021 E/M guidelines, the CMS CLIA-waived (QW) list, CMS global periods, and NCCI modifier 25 policy. The FHIR server is a local stand-in, not athenahealth's API.

Model

claude-opus-5-5 at low effort, structured JSON output. It never sees the billed level. 90 readings, $0.80 in total, median 1.7 s each (the first prompt's 90 readings cost $0.76). Its MDM grades matched the hand labels on 88 of 90 readings.

Run it yourself

Python 3.10+. Re-grading the recorded readings needs no API key.
